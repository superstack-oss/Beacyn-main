Code Review: Beacyn-EMO / PulseIQ
🔴 Critical Security Issues
1. Hardcoded credentials in frontend source (LoginForm.tsx, lines 16–17)

TSX
const [username, setUsername] = useState('root@beacyn.com');
const [password, setPassword] = useState('Root@Beacyn#26');

Default credentials are pre-filled in the login form and shipped in the frontend bundle — visible to anyone who inspects the JavaScript. Remove default values entirely.

2. Hardcoded seeded admin passwords in server code (server.ts, lines 1764 & 1791)

ts
[hashPassword('Root@Beacyn#26')]
[hashPassword('Svc@Beacyn#26')]

Both the super-admin and service account passwords are hardcoded in plaintext in the repository. Anyone with repo access knows the default passwords. These should come from a secure bootstrap mechanism (environment variable, first-run prompt, or external secret).

3. SHA-256 password hashing without a salt (server.ts, lines 98–100)

ts
function hashPassword(plain: string): string {
  return crypto.createHash('sha256').update(String(plain)).digest('hex');
}
Raw SHA-256 with no salt is vulnerable to rainbow-table and dictionary attacks. Replace with bcrypt, argon2, or Node's built-in crypto.scrypt.

4. Weak fallback session secret (server.ts, line 94)

ts
const SESSION_SECRET = String(process.env.SESSION_SECRET || process.env.JWT_SECRET || 'pulseiq-dev-session-secret').trim();
The plaintext fallback 'pulseiq-dev-session-secret' is publicly known from the repository. Anyone who reads this file can forge valid session tokens when SESSION_SECRET isn't set in the environment.

5. Legacy admin/admin backdoor (server.ts, lines 6183–6210)

ts
if (err?.code === 'ER_NO_SUCH_TABLE') {
  if (String(username) === 'admin' && String(password) === 'admin') { // grants token
When the users table doesn't exist, the login endpoint falls back to accepting admin/admin. Even if this path is rarely hit in production, it should be removed.

6. No rate limiting on auth endpoints
POST /api/auth/login and POST /api/auth/register have no rate limiting or brute-force protection. Add a library like express-rate-limit with a sensible window (e.g., 10 attempts/15 min per IP) on all auth routes.

🟠 High-Severity Security Issues
7. Wildcard CORS (server.ts, line 634)

ts
app.use(cors());
cors() with no options allows any origin. Restrict the allowed origins to the known frontend domain:

ts
app.use(cors({ origin: process.env.ALLOWED_ORIGIN || 'http://localhost:5173' }));
8. Unauthenticated agent ingestion endpoints
POST /api/agents/heartbeat, /api/agents/metrics, /api/agents/health, /api/databases/ingest accept and persist arbitrary data from any caller with no authentication. An attacker can flood the database or spoof agent data. These endpoints should require at minimum a pre-shared API key.

9. Unauthenticated monitoring/probe endpoints
GET /api/monitor/website, /api/monitor/ping, /api/monitor/ssl, /api/monitor/port accept arbitrary user-supplied hostnames/URLs with no authentication. This is a classic SSRF (Server-Side Request Forgery) surface — anyone on the internet can use your server to probe internal hosts. These should require a valid session.

10. Unauthenticated /api/observability/summary (server.ts, line 645)
This endpoint returns detailed internal metrics and table statistics to unauthenticated callers.

11. X-Forwarded-For header trusted unconditionally (server.ts, lines 151–157)

ts
const forwardedFor = String(req.headers?.['x-forwarded-for'] || '').trim();
if (forwardedFor) { const first = forwardedFor.split(',')[0]?.trim(); ... }
Any client can spoof this header to appear as 127.0.0.1, bypassing isMonitorRequestAuthorized's local-IP exemption. Trust this header only when behind a known reverse proxy.

12. SNMP v3 credentials stored in plaintext (server.ts, lines 1900–1905)
auth_key and priv_key are stored in the snmp_devices table as plain VARCHAR(255). These should be encrypted at rest.

13. Raw error messages returned to clients
Multiple catch blocks do res.status(500).json({ error: err.message }) (e.g., login endpoint line 6222), leaking stack traces or SQL error details. Return generic error messages to clients and log details server-side.

🟡 Medium-Severity Issues
14. No request body size limits

ts
app.use(express.json());
Without a limit option, a client can send arbitrarily large JSON payloads, enabling DoS via memory exhaustion. Add: app.use(express.json({ limit: '1mb' })).

15. Token comparison is not timing-safe (server.ts, line 113)

ts
if (signature !== expected) return null;
String comparison with !== leaks timing information. Use crypto.timingSafeEqual(Buffer.from(signature), Buffer.from(expected)).

16. In-memory session store is not persistent

ts
const sessions = new Map<string, SessionEntry>();
All active sessions are lost on server restart, forcing all users to log out. Consider a Redis-backed store or a signed-cookie approach.

17. No session expiry cleanup for the in-memory Map
Expired sessions accumulate indefinitely in the sessions Map until the process restarts. Add periodic cleanup of entries where expiresAt < Date.now().

18. xlsx package with known vulnerabilities (package.json, line 44)

JSON
"xlsx": "^0.18.5"
The SheetJS community (xlsx) package at this version has known security advisories. Evaluate whether this dependency is necessary and consider switching to a maintained alternative (e.g., exceljs).

🔵 Code Quality / Maintainability Issues
19. server.ts is a 405 KB monolith
The single server file contains authentication, CRUD for 10+ domains, SNMP polling, syslog ingestion, status pages, observability, and more. It should be split into Express routers organized by domain (e.g., routes/auth.ts, routes/assets.ts, routes/snmp.ts).

20. Pervasive any typing
Nearly every database result is cast as any:

ts
const [rows]: any = await pool.query(...)
Define proper types or use a lightweight ORM. This eliminates TypeScript's main safety benefit.

21. Schema migrations baked into application startup
Dozens of CREATE TABLE IF NOT EXISTS and ALTER TABLE calls run at startup. This approach is fragile (race conditions, no rollback, no history). Use a proper migration tool (e.g., db-migrate, Flyway, Knex migrations).

22. Admin settings leak AI API keys to frontend
The GET /api/settings endpoint merges adminSettings (which includes aiApiKey, smtpPass, snowToken) into the response for admin users. These secrets should never leave the server.

23. package.json name is still vite-project
The project was never given a proper name in package.json (line 2: "name": "vite-project"). This is a cosmetic issue but suggests the project setup was incomplete.

24. Audit log retention is only 7 days (server.ts, line 1394)

ts
await pool.query(`DELETE FROM portal_audit_logs WHERE created_at < (UTC_TIMESTAMP() - INTERVAL 7 DAY)`);
Seven-day audit retention is insufficient for most compliance requirements (SOC 2, ISO 27001 require 90 days–1 year). Make this configurable or extend the default.
