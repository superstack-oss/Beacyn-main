# Beacyn Service Management (`beacynctl`)

`beacynctl` is the Beacyn platform management CLI. It wraps all day-to-day operations — starting and stopping the service, reading logs, managing configuration, running database backups, and more — into a single command available from any terminal after installation.

**CLI version**: `1.0.0`  
**Implementation**: `src/scripts/cli/beacynctl.sh`  
**Installer**: `src/scripts/cli/install-beacynctl.sh`  
**Config file**: `src/scripts/cli/.beacynctl.env` (generated at install time, permissions `600`)

---

## Account Setup for BeacynCTL

### What Gets Installed

Running the Beacyn installer creates two files that wire up `beacynctl` to your installation:

| File | Location | Purpose |
|---|---|---|
| `beacynctl` (executable) | `<INSTALL_DIR>/bin/beacynctl` | The CLI binary copied from `src/scripts/cli/beacynctl.sh` |
| `.beacynctl.env` | `src/scripts/cli/.beacynctl.env` | Runtime config generated at install time, permissions `600` |

The config file records everything `beacynctl` needs to find and manage your Beacyn service. A sample generated config:

```ini
# Generated by install-beacynctl.sh
APP_DIR=/path/to/your/beacyn
ENV_FILE=/path/to/your/beacyn/.env
SERVICE_MANAGER=launchd           # launchd | systemd | nohup
SERVICE_NAME=beacyn
PLIST_LABEL=io.beacyn.platform.<username>
PLIST_FILE=/Users/<username>/Library/LaunchAgents/io.beacyn.platform.<username>.plist
LOG_FILE=/Users/<username>/.beacyn/logs/beacyn.log
ERROR_LOG_FILE=/Users/<username>/.beacyn/logs/beacyn-error.log
PID_FILE=/path/to/your/beacyn/.beacyn.pid
FRONTEND_URL=http://localhost:7145
BACKEND_URL=http://localhost:5145
FRONTEND_PORT=7145
BACKEND_PORT=5145
NPM_BIN=npm
```

> The config file is automatically created by `install-beacynctl.sh`. You do not need to edit it manually unless you are migrating to a different install location.

### Installation: Fresh Install

If you are installing Beacyn for the first time, `beacynctl` is set up automatically by the main installer:

```bash
cd <your-beacyn-directory>
chmod +x deployment/install.sh
./deployment/install.sh
```

The installer calls `src/scripts/cli/install-beacynctl.sh` internally with the flags it discovers during setup. After the installer finishes, `bin/beacynctl` exists and `.beacynctl.env` is populated.

### Installation: Existing Install

If Beacyn is already running and you need to regenerate or repair `beacynctl`:

```bash
cd <your-beacyn-directory>
bash src/scripts/cli/install-beacynctl.sh \
  --app-dir "$PWD" \
  --env-file "$PWD/.env" \
  --service-manager launchd \
  --service-name beacyn \
  --plist-label "io.beacyn.platform.$USER" \
  --plist-file "$HOME/Library/LaunchAgents/io.beacyn.platform.$USER.plist" \
  --log-file "$HOME/.beacyn/logs/beacyn.log" \
  --error-log-file "$HOME/.beacyn/logs/beacyn-error.log" \
  --frontend-url "http://localhost:7145" \
  --backend-url "http://localhost:5145"
```

Replace `--service-manager launchd` with `systemd` on Linux or `nohup` for plain background process deployments.

### Installer Flags Reference

| Flag | Description |
|---|---|
| `--app-dir` | Root directory of the Beacyn installation (required) |
| `--env-file` | Path to the application `.env` file (required) |
| `--service-manager` | `launchd`, `systemd`, or `nohup` (required) |
| `--service-name` | Service unit name (default: `beacyn`) |
| `--plist-label` | macOS LaunchAgent label (e.g., `io.beacyn.platform.$USER`) |
| `--plist-file` | Full path to the `.plist` file (macOS only) |
| `--log-file` | Path to the primary log file |
| `--error-log-file` | Path to the error log file |
| `--frontend-url` | Full frontend URL (default: `http://localhost:7145`) |
| `--backend-url` | Full backend API URL (default: `http://localhost:5145`) |
| `--frontend-port` | Frontend port number (default: `7145`) |
| `--backend-port` | Backend port number (default: `5145`) |
| `--npm-bin` | npm binary name (default: `npm`) |
| `--auto-path` | `true` / `false` — auto-add `bin/` to shell profile PATH |

### PATH Setup

After installation, `beacynctl` lives at `<INSTALL_DIR>/bin/beacynctl`. To run it as `beacynctl` from any terminal, add the `bin/` directory to your PATH.

**Automatic PATH setup** (recommended):

Pass `--auto-path true` to the installer or set `BEACYNCTL_AUTO_PATH=true`:

```bash
BEACYNCTL_AUTO_PATH=true ./deployment/install.sh
```

The installer detects your OS and shell and writes the export line to the appropriate profile:

| Platform | Shell | Profile modified |
|---|---|---|
| macOS | zsh (default) | `~/.zshrc` |
| macOS | bash | `~/.bashrc` |
| Linux | zsh | `~/.zshrc` |
| Linux | bash | `~/.bashrc` |
| Windows | PowerShell | User PATH environment variable |

**Manual PATH setup**:

If you did not use `--auto-path`, add the line yourself:

```bash
# macOS / Linux (zsh)
echo 'export PATH="<INSTALL_DIR>/bin:$PATH"' >> ~/.zshrc && source ~/.zshrc

# macOS / Linux (bash)
echo 'export PATH="<INSTALL_DIR>/bin:$PATH"' >> ~/.bashrc && source ~/.bashrc
```

```powershell
# Windows (PowerShell — current user)
[Environment]::SetEnvironmentVariable("Path", "$env:Path;<INSTALL_DIR>\bin", "User")
```

Restart the terminal after any manual PATH change.

Optional symlink locations (if those directories are already in PATH):
- `/usr/local/bin/beacynctl`
- `~/.local/bin/beacynctl`

### Background Service Behavior

Beacyn runs as a managed background service after installation:

| Platform | Service Manager | Behavior |
|---|---|---|
| macOS | `launchd` (LaunchAgent) | Starts at login, runs in background, survives terminal close |
| Linux | `systemd` | Runs as a system unit, restarts on failure |
| Any | `nohup` (fallback) | Background process — does not auto-restart |

`beacynctl` detects which service manager is active from `.beacynctl.env` and routes all start/stop/restart operations accordingly.

### Resolving Config Errors

If you see:

```text
beacynctl config file not found: /path/.../src/scripts/cli/.beacynctl.env
```

You are likely running a stale symlink or old wrapper. Use the absolute binary directly:

```bash
<INSTALL_DIR>/bin/beacynctl status
```

Then re-run the installer or fix PATH to point at the current `<INSTALL_DIR>/bin` as shown above.

`beacynctl` checks three config locations in order:
1. `<APP_DIR>/src/scripts/cli/.beacynctl.env` ← primary
2. `<APP_DIR>/cli/.beacynctl.env` ← legacy fallback
3. `<APP_DIR>/.beacynctl.env` ← legacy fallback

## Using BeacynCTL

### Global Syntax

```bash
beacynctl <command> [options]
```

### Checking If Everything Is Running

```bash
beacynctl status
```

Prints a full status report:

```
Beacyn Platform Status
Service manager: launchd
Service state:   running
Service PID:     12345
Frontend URL:    http://localhost:7145
Backend URL:     http://localhost:5145
Frontend port:   7145 (listening: yes)
Backend port:    5145 (listening: yes)
Frontend HTTP:   200
Backend HTTP:    200
Log file:        /Users/<user>/.beacyn/logs/beacyn.log
Error log:       /Users/<user>/.beacyn/logs/beacyn-error.log
```

For automation or CI use `--json` to get machine-readable output:

```bash
beacynctl status --json
```

### Quick Health Probe

```bash
beacynctl health
```

Returns `healthy` (exit code `0`) or `unhealthy` (non-zero exit). Checks:
- Frontend port is listening
- Backend port is listening
- Frontend returns HTTP 200
- Backend returns HTTP 200

Suitable for use in health check scripts or CI pipelines.

### Starting and Stopping

```bash
beacynctl start      # start the service
beacynctl stop       # stop the service
beacynctl restart    # full restart (stop + start)
```

### Reading Logs

```bash
beacynctl logs                        # last 80 lines from all components
beacynctl logs -f                     # follow (live tail)
beacynctl logs --tail 200             # last 200 lines
beacynctl logs --component backend    # filter to backend entries
beacynctl logs --component security   # filter to security entries
beacynctl logs --component frontend -f
```

On Linux with `systemd`, `logs` delegates to `journalctl -u beacyn` automatically.

### Opening the Portal

```bash
beacynctl open
```

Opens the frontend (`http://localhost:7145`) and backend (`http://localhost:5145`) in your default browser using `open` (macOS) or `xdg-open` (Linux).

### Managing Environment Variables

Use `config` or its `env` alias to read and write the application `.env` without editing the file manually:

```bash
beacynctl env list                      # show all app env vars (sensitive values masked)
beacynctl env get DB_HOST               # read a single key
beacynctl env set DB_HOST 10.0.0.5      # write a key to .env
beacynctl env unset DB_HOST             # remove a key from .env
```

To manage the `beacynctl` metadata config instead of the app `.env`:

```bash
beacynctl config list --cli             # show CLI config keys
beacynctl config set BACKEND_PORT 5145 --cli
```

> Sensitive keys containing `PASS`, `PASSWORD`, `KEY`, `TOKEN`, or `SECRET` are automatically masked in `list` output.

### Database Operations

**Schema-only backup** (safe default — no data, just DDL):

```bash
beacynctl backup
```

**Full data backup**:

```bash
beacynctl backup --with-data --output ./backups
```

Creates two SQL dump files in the output directory:
- `pulseiq-<timestamp>.sql` — application database
- `bsa-<timestamp>.sql` — infrastructure assets database

**Run database migrations**:

```bash
beacynctl migrate
```

Runs `npm run initdb` from the application directory.

### Diagnostics and Troubleshooting

```bash
beacynctl validate    # check required files and binaries exist
beacynctl doctor      # comprehensive report: status + validate + disk + node version + recent logs
beacynctl self-test   # validate + health in one command
beacynctl audit       # npm dependency audit + config file permission check
```

**Standard troubleshooting workflow**:

```bash
# 1 — check overall state
beacynctl status

# 2 — restart if needed
beacynctl restart

# 3 — inspect recent errors
beacynctl logs --tail 100

# 4 — follow live output
beacynctl logs -f

# 5 — open in browser to confirm
beacynctl open
```

### Support Snapshot

Creates a support bundle containing status JSON, log tails, and a sanitized env file. Useful when filing a bug report or escalating to support:

```bash
beacynctl snapshot
beacynctl snapshot --output ./snapshots
```

Output is a `.tar.gz` archive containing:
- `status.json` — machine-readable service status
- `log-tail.txt` — last 200 lines of the main log
- `error-log-tail.txt` — last 200 lines of the error log
- `env-sanitized.txt` — `.env` file with all sensitive values replaced with `****`

### Maintenance Mode

```bash
beacynctl maintenance on      # enable maintenance flag
beacynctl maintenance off     # disable maintenance flag
beacynctl maintenance status  # check current state (default)
```

### Password Reset

Reset the `Root-user` password (or any other user) from the CLI without needing portal access:

```bash
beacynctl reset-password                         # prompts for password (hidden input)
beacynctl reset-password --user Root-user        # explicit user, prompts for password
beacynctl reset-password --user admin --password <value>
```

Password is hashed with SHA-256 before being written to the database.

### Cleanup

Remove accumulated logs, cache files, and snapshots:

```bash
beacynctl cleanup --scope logs --yes        # remove log files
beacynctl cleanup --scope snapshots --yes   # remove snapshot archives
beacynctl cleanup --scope all --yes         # remove everything
beacynctl cleanup --scope all --yes --include-db   # also clear DB transient data
```

> `--yes` is required as a safety gate. Without it, the command refuses to run.

### Direct Service Commands (Without `beacynctl`)

These are useful when `beacynctl` itself is unavailable.

**macOS (`launchd`)**:

```bash
# Stop
launchctl bootout "gui/$(id -u)/io.beacyn.platform.$USER"

# Start
launchctl bootstrap "gui/$(id -u)" "$HOME/Library/LaunchAgents/io.beacyn.platform.$USER.plist"
launchctl kickstart -k "gui/$(id -u)/io.beacyn.platform.$USER"

# Status
launchctl print "gui/$(id -u)/io.beacyn.platform.$USER"
```

**Linux (`systemd`)**:

```bash
sudo systemctl status beacyn
sudo systemctl start beacyn
sudo systemctl stop beacyn
sudo systemctl restart beacyn
sudo journalctl -u beacyn -f
```

**Verify ports / HTTP directly**:

```bash
lsof -nP -iTCP:5145 -sTCP:LISTEN
lsof -nP -iTCP:7145 -sTCP:LISTEN

curl -s -o /dev/null -w "backend=%{http_code}\n" http://localhost:5145
curl -s -o /dev/null -w "frontend=%{http_code}\n" http://localhost:7145
```

## Command Reference

### `status`

```bash
beacynctl status [--json]
```

Shows service manager type, service state, PID, port listening status, HTTP status codes, and log paths.

| Flag | Description |
|---|---|
| `--json` | Machine-readable JSON output for automation/CI |

**Safe default**: human-readable text output.

---

### `health`

```bash
beacynctl health
```

Checks frontend and backend ports are listening and return HTTP 200. Prints `healthy` or `unhealthy`.

| Exit code | Meaning |
|---|---|
| `0` | All checks passed |
| non-zero | One or more checks failed |

---

### `start`

```bash
beacynctl start
```

Starts the service using the configured service manager (`launchd`, `systemd`, or `nohup` fallback). Prints status after start.

---

### `stop`

```bash
beacynctl stop
```

Stops the service using the configured service manager.

---

### `restart`

```bash
beacynctl restart [--component <backend|frontend|security|all>]
```

Stops then starts the service. Component-level restart requests fall back to a full restart when the service manager does not support isolation.

**Safe default**: full restart.

---

### `logs`

```bash
beacynctl logs [--component <backend|frontend|security|all>] [--tail N] [-f|--follow]
```

| Flag | Default | Description |
|---|---|---|
| `--component` | `all` | Filter log output to a named component |
| `--tail N` | `80` | Number of lines to display |
| `-f` / `--follow` | disabled | Live tail (like `tail -f`) |

On `systemd`, delegates to `journalctl -u <service-name>`.

---

### `open`

```bash
beacynctl open
```

Opens `FRONTEND_URL` and `BACKEND_URL` in the default browser. Uses `open` on macOS and `xdg-open` on Linux. Falls back to printing the URLs if neither is available.

---

### `config`

```bash
beacynctl config list   [--env|--cli|--all]
beacynctl config get    KEY [--env|--cli]
beacynctl config set    KEY VALUE [--env|--cli]
beacynctl config unset  KEY [--env|--cli]
beacynctl config validate
```

| Scope | Target file |
|---|---|
| `--env` | Application `.env` file |
| `--cli` | `src/scripts/cli/.beacynctl.env` |
| `--all` | Both files |

**Safe defaults**: `list` uses `--all`; `set` / `unset` default to `--env`. Sensitive values are masked in `list`.

---

### `env`

```bash
beacynctl env list
beacynctl env get KEY
beacynctl env set KEY VALUE
beacynctl env unset KEY
```

Convenience alias for `config --env`. All operations target the application `.env` file.

---

### `backup`

```bash
beacynctl backup [--schema-only|--with-data] [--output DIR]
```

Dumps both `pulseiq` and `bsa` databases using `mysqldump`. Reads database credentials from `.env` (`DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`).

| Flag | Default | Description |
|---|---|---|
| `--schema-only` | ✓ (default) | DDL only — no row data |
| `--with-data` | — | Include all table data |
| `--output DIR` | `<APP_DIR>/backups` | Output directory |

Output files: `pulseiq-<YYYYMMDD-HHMMSS>.sql` and `bsa-<YYYYMMDD-HHMMSS>.sql`.

---

### `snapshot`

```bash
beacynctl snapshot [--output DIR]
```

Creates a support bundle as a `.tar.gz` archive containing:
- `status.json`
- `log-tail.txt` (last 200 lines)
- `error-log-tail.txt` (last 200 lines)
- `env-sanitized.txt` (sensitive values redacted)

**Safe default output**: `<APP_DIR>/snapshots`.

---

### `migrate`

```bash
beacynctl migrate
```

Runs `npm run initdb` from the application directory. Use after initial install or when applying schema updates.

---

### `validate`

```bash
beacynctl validate
```

Checks that required files (`package.json`, `.env`, `src/scripts/start.ts`) exist and that `node` and `npm` are available. Exits non-zero if any check fails.

---

### `expose`

```bash
beacynctl expose
```

Prints recommended options for exposing Beacyn to external networks (Cloudflare Tunnel, NGINX, ngrok) plus the current `FRONTEND_URL` and `BACKEND_URL`.

---

### `shell`

```bash
beacynctl shell
```

Drops into an interactive shell (`$SHELL` or `/bin/bash`) with the application directory as the working directory and all `.env` variables loaded into the environment.

---

### `reset-password`

```bash
beacynctl reset-password [--user USER] [--password VALUE]
```

| Flag | Default | Description |
|---|---|---|
| `--user` | `Root-user` | Username to update |
| `--password` | _(prompt)_ | New password. If omitted, prompts interactively with hidden input |

Password is hashed with SHA-256 (via `shasum -a 256` or `openssl dgst -sha256`) before the database update. Database credentials are read from `.env`.

---

### `maintenance`

```bash
beacynctl maintenance [on|off|status]
```

Manages a `.maintenance-mode` flag file in the application directory.

| Subcommand | Action |
|---|---|
| `on` | Creates the flag file |
| `off` | Removes the flag file |
| `status` | Reports whether maintenance mode is active |

**Safe default**: `status`.

---

### `self-test`

```bash
beacynctl self-test
```

Runs `validate` followed by `health`. Exits non-zero if either check fails.

---

### `doctor`

```bash
beacynctl doctor
```

Produces a broad diagnostics report covering:
- Full `status` output
- `validate` results
- Disk usage for the app directory
- Node.js and npm version
- Last 40 log lines

Useful as the first step when something is wrong and you need a complete picture quickly.

---

### `version`

```bash
beacynctl version
```

Displays:
- `beacynctl` CLI version (currently `1.0.0`)
- App version from `package.json`
- Active service manager

---

### `audit`

```bash
beacynctl audit
```

Runs `npm audit --omit=dev` for dependency vulnerabilities and prints the permission bits of `.env` and `.beacynctl.env`. Use periodically or as part of a security review cycle.

---

### `cleanup`

```bash
beacynctl cleanup [--scope logs|cache|snapshots|all] [--yes] [--include-db]
```

| Flag | Default | Description |
|---|---|---|
| `--scope` | `all` | What to clean: `logs`, `cache`, `snapshots`, or `all` |
| `--yes` | required | Safety gate — command refuses to run without it |
| `--include-db` | disabled | Also clean transient database data |

---

### `uninstall`

```bash
beacynctl uninstall [--yes] [--keep-data] [--remove-db]
```

| Flag | Default | Description |
|---|---|---|
| `--yes` | required | Safety gate — refuses without it |
| `--keep-data` | _(data removed)_ | Preserve the application directory |
| `--remove-db` | _(DB kept)_ | Drop the databases during uninstall |

Stops the service, removes the service registration (launchd plist / systemd unit), removes `beacynctl` symlinks, and optionally removes the application directory and databases.

---

### `help`

```bash
beacynctl help
beacynctl --help
beacynctl -h
```

Prints the full command listing with usage examples.
